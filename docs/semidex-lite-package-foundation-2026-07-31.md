# Semidex Lite — package foundation (2026-07-31)

Status: foundation implemented, verified offline and live. Not published.
Do not commit or publish anything from this work without a separate,
explicit decision — this report documents what exists, not a release.

Design rationale, the closure-validator's five checks, and full detail on
every refactor: `docs/design/semidex-lite-package-boundary.md`. This report
covers what was built, how it was verified, and what remains.

## Architecture summary

`semidex-lite` is a same-repo-staged npm package
(`packages/lite/`, gitignored `src/`/`dist/`, regenerated by
`packages/lite/build.mjs` on every `npm pack`/`npm publish` via the
`prepack` hook) — not npm workspaces, not `optionalDependencies`. It reuses
the full Semidex `src/` tree with four backward-compatible source
refactors (Refactors 1–4, see the design doc) rather than forking code.

Four rejected alternatives, and why:

- **Fork the repo entirely.** Guarantees permanent drift between two
  copies of the same chunking/retrieval/Ask logic; rejected outright.
- **npm workspaces.** The correct long-term shape, but a much larger
  structural change than a first foundation warrants — deferred.
- **`optionalDependencies` for the heavy natives.** Does not actually
  prevent installation in most real npm configurations; "optional" is not
  "excluded by default."
- **Ship the same admin UI bundle for both, skip the Vite build split.**
  Considered once the settings view turned out to already be almost
  entirely data-driven (no separate build needed for most of it) — but
  rejected because two genuinely static, unconditional local-only markup
  blocks (the ONNX probe panel template, and the ONNX/LLM-summaries/
  tag-gen checkboxes on two separate indexing forms) can only be removed
  by a real build-time strip, and the plan's own requirement was
  "compiled OUT, not CSS-hidden, not regex-stripped [of runtime markup]."

125 files packed, 383.9 kB compressed / 1.3 MB unpacked (`npm pack`
output). 116 `.js` runtime files under `packages/lite/src/`, plus
`bin/semidex-lite.js`, `lite-src/*.js` (5 files: the CLI composition
layer — `hard-pins.js`, `semidex-home.js`, `doctor-lite.js`,
`serve-lite.js`, `index-lite.js`), the built `dist/admin-ui/` (3 files:
`index.html`, one CSS bundle, one JS bundle), `README.md`, `.env.example`,
`package.json`.

`packages/lite/package.json` `dependencies`: `@google/genai`,
`@huggingface/tokenizers`, `@opendocsg/pdf2md`, `@qdrant/js-client-rest`,
`dotenv`, `franc-min`, `pdf-parse`, `remark-frontmatter`, `remark-gfm`,
`remark-parse`, `unified`. Every entry verified as a genuine runtime
dependency of staged code via the closure validator's check #4 (bare
specifiers not in `dependencies` fail the build) — not asserted by
inspection.

Explicitly **not** included, verified absent from the installed tree via
`npm ls --all` in the clean-install acceptance test:

- `onnxruntime-node`, `@huggingface/transformers` — the two heavy natives.
- `highlight.js` — confirmed to be a Vite-build-time-only dependency of
  the admin UI (bundled into the built JS, never imported by any
  server-side staged file).
- `acorn`/`acorn-walk` — the closure validator's own parser, a **root**
  `devDependency`, never shipped in the Lite package itself.

## Clean-install commands and results

```bash
cd packages/lite
npm pack                       # runs prepack (build.mjs) first
npm install <path-to>.tgz      # into a FRESH temp dir, outside the repo
```

Automated as `tests/unit/lite/clean-install-acceptance.test.js` (6 tests,
all passing): installs the real packed tarball into an empty temp
directory, marks the installed `node_modules/semidex-lite/` **read-only**,
then runs `--help`, `doctor` (missing-credential env → clean exit 1, never
a crash), and `serve` (real `/api/health` HTTP round-trip) against the
read-only install — plus an acorn-based static check that every relative
import in the installed package resolves to a path inside the package
directory (no `../../../` escape). `npm ls --all` confirms
`onnxruntime-node`/`@huggingface/transformers`/`acorn` are absent from the
131-package installed dependency tree.

This exact test suite caught a real packaging bug before it could ship:
`lite-src/*.js` used `../../../src/...` import paths (correct for the
repo layout, wrong once packaged — see the design doc's "Clean-install
acceptance" section for the full explanation). Fixed in all three
`lite-src/` files.

## Live acceptance result (2026-07-31, against the user's real dev Qdrant Cloud cluster and Gemini API)

Sequence run: `doctor` (read-only) → `doctor --probe-inference` (real,
disposable embedding round-trip) → index a 2-file, English+Ukrainian
fixture (one `.md`, one `.txt` — exercising both the skeleton and the
deterministic-legacy-context paths) into a uniquely-prefixed disposable
collection → Ukrainian-language hybrid search → one Gemini Ask request →
delete the disposable collection.

**Result: full success**, after finding and fixing three real bugs
mid-run (see the design doc's "What a live vertical slice caught" section
for the technical detail of each):

1. `doctor-lite.js` checked the wrong success-status string for the Cloud
   Inference probe (`'ok'` vs. the real `'inference_available'`) —
   probe-inference silently reported FAIL on every actual success.
2. `shutdownOnnxTagWorker()` threw unconditionally in the Lite shim, but
   `run.js` calls it as unconditional per-run cleanup regardless of
   whether tagging was ever used — crashed indexing on the second file of
   every run.
3. The Ollama-preflight gate and the context-generation call site were
   gated on two different conditions — a legacy (non-Markdown) file under
   `CONTEXT_MODE=deterministic` still tripped the preflight check.

All three fixed, covered by new unit tests, and re-verified live after the
fixes: indexing completed cleanly (both files, exit code 0), the Ukrainian
query returned correctly ranked hybrid results across both files with
intact UTF-8 payloads, and the Gemini Ask request returned a
correctly-cited, grounded streamed answer (`gemini-flash-latest`,
412 prompt tokens / 89 completion tokens, 3 citations, `refused: false`).
One transient `fetch failed` network error occurred on the first Ask
attempt and resolved on retry — confirmed not a code defect (evidence
retrieval, the Semidex-Lite-specific part of the request, succeeded
identically on both attempts; only the raw Gemini network call failed
once).

Disposable collection deleted and verified gone (`404` on a follow-up
`GET`). The real repo's own `config.json`/`settings.json` were confirmed
untouched throughout — all live-slice state landed in an isolated
`SEMIDEX_HOME` temp directory that was removed afterward. No endpoint,
key, full prompt, or full answer text is reproduced in this report beyond
what's shown above (model id, token counts, citation count, timing).

## Remaining limitations / next recommended task

- **Not published, not workspace-integrated.** This is a same-repo-staged
  foundation; publishing to npm, or migrating to a real workspace layout,
  is a distinct, separately-scoped decision this work deliberately did
  not make.
- **No CI wiring.** `packages/lite/build.mjs` and the Lite test suites run
  on demand (`npm run admin:build:lite`, `node packages/lite/build.mjs`,
  the `tests/unit/lite/**` suite) but are not yet part of any CI pipeline
  — a regression in the closure boundary would currently only be caught
  by someone running these manually.
- **`packages/lite/README.md` has not been read by a second person** —
  it documents the CLI, `SEMIDEX_HOME`, and the feature-parity table, but
  has not been proofread against a genuinely fresh (non-author)
  perspective.
- **Version `1.0.0` in `packages/lite/package.json` is a placeholder** —
  no version-numbering decision has been made (independent Lite
  versioning vs. tracking full Semidex's own version).
- **Live acceptance covered one dense model** (`intfloat/multilingual-e5-small`,
  the free/default supported model) and one small, two-file, two-language
  fixture — not a stress test, not a coverage sweep across every supported
  Qdrant Cloud model or file format Pandoc can convert.

**Next recommended task**: wire `packages/lite/build.mjs`'s closure
validator and the `tests/unit/lite/**` suite into CI, gated on any change
under `src/` or `packages/lite/`, so a future refactor that reintroduces a
static edge to an excluded module (the exact class of bug this whole
foundation exists to prevent) fails a PR check rather than requiring a
manual live run to discover.
