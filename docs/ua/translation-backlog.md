# Backlog перекладів deep-dive документації (укр.)

Зараз українською є лише `docs/ua/README.md`. Англійські deep-dive docs (`docs/en/`)
ще не перекладені. Нижче — порядок перекладу за користю для нового користувача.
**Не перекладати:** benchmark-звіти (`benchmarks/.../results/`), ADR
(`docs/adr/`), чернеткові design docs (`docs/design/`) — вони технічні й/або змінні.

| # | Документ (`docs/en/`) | Чому варто перекласти | Пріоритет |
|---|----------------------|------------------------|-----------|
| 1 | `operations.md` | Приклади використання, обмеження, troubleshooting — найпотрібніше новачку | Високий |
| 2 | `configuration.md` | Env-змінні, матриця підтримки платформ, формати — потрібно щоб запустити | Високий |
| 3 | `retrieval.md` | Гібридний пошук, провайдери, RRF, rerank — ядро ціннісної пропозиції | Високий |
| 4 | `architecture.md` | Як працює пайплайн індексації і що зберігається | Середній |
| 5 | `mcp-tools.md` | Довідник MCP-інструментів і робочі процеси агента | Середній |
| 6 | `roadmap.md` | Напрям продукту та послідовність майбутніх етапів | Середній |
| 7 | `chunking-quality.md` | Гарантії розбиття, режими помилок, метрики якості | Низький |
| 8 | `project-structure.md` | Дерево вихідників — для контриб'юторів, не для користувачів | Низький |
| 9 | `obsidian.md` | Obsidian-review вивід — нішевий сценарій | Низький |
| 10 | `benchmarking.md` | Гайд по бенчмарках — корисний, але технічний; не плутати зі звітами | Низький |

Виключено з перекладу (за вимогою): `benchmark-dataset-plan.md`, `ce-rerank-design.md`
(дизайн/план), усе у `docs/design/`, `docs/adr/`, `benchmarks/.../results/`.

Рекомендація: спочатку підтримувати актуальність `docs/ua/README.md`, а потім
перекласти 1–3 як наступний крок локалізації.
