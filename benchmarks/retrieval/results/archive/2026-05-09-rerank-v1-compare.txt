Analysis:

Rerank is neutral-to-slightly-negative on this corpus for onnx, and marginally
positive for ollama (q15: #4 → #3, MRR +0.004).

Root cause: q2 ("як перемкнутися на ONNX без Ollama") contains tokens "onnx" and
"ollama" which appear across multiple fixture files (not just providers.md).
The BOOST_TEXT signal promotes chunks from other files that happen to mention
these tokens, outweighing the base RRF score for providers.md.

This is expected behavior: deterministic token-boost reranking adds value when:
  1. RRF scores between correct/incorrect candidates are close, AND
  2. Query tokens are discriminative (unique to the correct file).

On this benchmark, onnx+RRF already retrieves nearly perfectly. Reranking has
little room to improve ranking quality but can introduce ordering noise.

Rerank shows more value on:
  - Queries with rare technical tokens (e.g. embedding_schema_version)
  - Larger corpora where RRF confidence is lower
  - Queries where the correct document is strongly identified by source_file name

Recommendation: keep RERANK_ENABLED=0 (default) for onnx production use.
Reranking remains available for opt-in experimentation and for future signals
(e.g. freshness, user feedback) that don't carry this cross-file noise risk.
