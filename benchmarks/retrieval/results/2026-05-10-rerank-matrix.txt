Analysis:

ollama+rerank apparent regression (q1 #1→#2):
  RERANK_DEBUG=1 run immediately after matrix confirmed providers.md is
  correctly scored #1 (baseScore=1.21 vs 0.53 for rank-2). The #2 result
  in the matrix is an artefact of RRF score variance between re-indexing
  runs: the matrix script re-indexes before each variant, and two separate
  ollama indexing passes can produce subtly different RRF fusion scores,
  putting a different chunk at Qdrant rank-0 and changing the top-1
  protection anchor. This is a measurement artefact, not a reranker bug.

  Confirmed: isolated debug run with BENCH_SKIP_INDEX=1 returns q1=#1
  for ollama+rerank. The matrix baseline (ollama, q1=#1) and the rerank
  variant hit different indexing passes.

ollama+rerank q15 stays #3:
  hashed-tf assigns uniform weight to "embedding_schema_version"; the
  reranker has no signal to distinguish it (section name "Reindex
  triggers" doesn't contain the query token). This is a hashed-tf
  limitation, not a reranker deficiency.

onnx+rerank q2 stays #2:
  "як перемкнутися на ONNX без Ollama" — the expected providers.md chunk
  competes with qdrant.md content that also discusses ONNX. Without a
  strong discriminating technical token in the query that maps uniquely
  to providers.md section/tags, rerank cannot improve over RRF.
  This is the same structural miss documented in 2026-05-09 results.

Recommendation:

  RERANK_ENABLED=0 (default) for both providers on this corpus.
  - ollama+rerank: apparent -5pp Recall@1 is a measurement artefact (see above),
    but matrix script cannot isolate re-indexing variance — caution warranted.
  - onnx+rerank: 0pp Recall@1 delta, +3ms overhead, MRR unchanged.
  Reranking adds value on larger corpora where RRF confidence is lower and
  diversity / token-boost signals have more room to distinguish documents.
