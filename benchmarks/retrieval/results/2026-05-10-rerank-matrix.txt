Analysis:

ollama+rerank: 0pp Recall@1 delta, MRR unchanged.
  q2 stays #2 (structural miss — query competes across files for RRF).
  q15 stays #3 (hashed-tf gives uniform weight to "embedding_schema_version";
  reranker has no section/tag signal to discriminate). Reranking has no negative
  effect on ollama on this corpus; top-1 protection prevents regressions.

onnx+rerank: 0pp Recall@1 delta, MRR unchanged.
  onnx baseline this run achieved 100% (q2 #1) — RRF variance between index
  passes; 2026-05-09 baseline had q2 at #2. Reranker correctly preserves all
  #1 results; no regressions introduced.

onnx baseline q2 variance:
  q2 was #2 on 2026-05-09, #1 today. ONNX neural sparse weights are deterministic
  per text, but RRF fusion scores depend on the full candidate set. Minor chunk
  score differences between index passes (different upsert timing, Qdrant internals)
  can flip borderline RRF ranks. This is expected for a corpus where two files
  compete closely for q2.

─────────────────────────────────────────────────────────────
Conclusion:

Reranking is neutral on this 20-query / 4-fixture corpus for both providers:
0pp Recall@1, 0 MRR delta, negligible latency overhead (~0ms real; cold-start
artefact excluded).

The 2026-05-09 rerank-v2 result (onnx 100% with rerank, 95% without) was likely
a favourable onnx baseline run where q2 was already at #2 without rerank, and
the reranker moved it to #1. Today's onnx baseline already hits 100% without
rerank, so the reranker has no room to improve further.

RERANK_ENABLED=0 remains the correct default. Reranking benefit would appear
on a larger or more ambiguous corpus where RRF confidence is lower.
